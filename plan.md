# Agentic AI Research Agent — Architecture & Learning Guide

## 📌 Project Overview & Objectives

This project is an end-to-end, modular **Agentic AI Research Assistant** built from scratch in Python using LLMs (Groq / Google Gemini). The primary objective is educational: to explore and master every architectural component of an autonomous agent—including tool dispatching, lifecycle hooks, session memory, and multi-hop problem solving.

---

## 📋 Core Architectural Components

| # | Capability | Component | Description |
|---|------------|-----------|-------------|
| **1** | **Web-Search Skill** | `tools/search.py` | Web search integration (DuckDuckGo search for zero-setup free queries, with optional Tavily/SerpAPI fallback). |
| **2** | **Session Memory** | `agent/memory.py` | Working conversation buffer + Semantic Fact Store to recall facts provided earlier in the session. |
| **3** | **Lifecycle Hooks** | `agent/hooks.py` | Intercepts all tool invocations; logs pre/post execution events, arguments, execution duration, and ISO timestamps. |
| **4** | **File-Read Plugin** | `tools/file_reader.py`| Extensible plugin allowing the agent to inspect and extract text from local `.txt`, `.md`, and `.pdf` files. |
| **5** | **Multi-Hop Demo** | `main.py` | An interactive demo where a single query triggers local file reading, web search, memory recall, and timestamped hook logging. |

## 🧠 Deep Dive: Core Concepts to Learn

### Concept 1: Function Calling & Tool Schemas (`tools/`)
LLMs cannot run code directly. Instead:
1. We give the LLM a list of available tool definitions (schemas) specifying:
   - Tool Name (e.g., `web_search`)
   - Description (what it does and when to call it)
   - Parameters (required inputs and data types)
2. When the LLM needs external information, it emits a structured function call:
   `{"name": "web_search", "args": {"query": "Quantum computing latest milestone 2026"}}`
3. Our Python agent catches the request, executes the corresponding Python function, and returns the result to the LLM.

### Concept 2: Lifecycle Hooks (`agent/hooks.py`)
A **Hook** is a callback that listens to events in the agent lifecycle without altering business logic.
- **Hook Lifecycle Stages:**
  - `on_tool_start(tool_name, tool_args, timestamp)`: Captures start time ($t_0$), arguments, and logs the intent.
  - `on_tool_end(tool_name, tool_args, tool_output, duration_ms, timestamp)`: Captures end time ($t_1$), elapsed latency, output size, and success status.
  - `on_tool_error(tool_name, tool_args, error, duration_ms, timestamp)`: Captures exceptions and error states.
- Every event is recorded with an ISO 8601 timestamp (e.g., `2026-09-09T12:00:00Z`).

### Concept 3: Session Memory System (`agent/memory.py`)
Memory consists of two layers:
1. **Conversation History Buffer:** Retains recent dialog turns for conversational context.
2. **Fact Recall Store:** Stores critical facts, user preferences, and intermediate findings explicitly tagged for recall across multi-step conversations.

### Concept 4: Multi-Hop Reasoning (`main.py`)
A **multi-hop question** requires chaining information across multiple independent sources:
```
User asks: "Based on the project PDF, who is the lead researcher, what recent 2026 paper did they publish, and how does it relate to the preference I told you earlier?"
  │
  ├── [Hop 1: File Plugin] ──> Reads local 'quantum_research_brief.pdf' (extracts researcher's name)
  │
  ├── [Hop 2: Web Search]  ──> Searches Web: "Dr. Elena Rostova recent publications 2026"
  │
  ├── [Hop 3: Memory]      ──> Recalls User Fact: "User is interested in Photonic Quantum computing"
  │
  └── [Synthesis]          ──> Synthesizes the final complete answer.
        ▲
        └─ Throughout all hops, [Hooks] record every tool call with exact timestamps and latency.
```
