# Agentic AI Research Agent — Implementation & Learning Plan (Week 4)

## 📌 Project Overview & Objectives

This project is an end-to-end, modular **Agentic AI Research Assistant** built from scratch in Python using the **Google Gemini** LLM API. The primary objective is educational: you will understand every architectural component of an agent—including tool dispatching, lifecycle hooks, session memory, and multi-hop problem solving.

**DuckDuckGo (DDG)** is a privacy-focused web search engine (like Google or Bing). 
- **Why we use it:** The Python library `duckduckgo-search` allows your Python program to query the web **for free, instantly, without creating any account, signing up, or entering credit cards**.
- **What you should do:** We will use DuckDuckGo as our default search engine. You do not need to sign up anywhere for search!

### 2. Google Gemini API Setup (Student Package / AI Studio)
Since you have access to Google Gemini:

3. Keep the key ready for your `.env` file (`GEMINI_API_KEY=your_key_here`).

## 🧠 Deep Dive: Core Concepts to Learn

### Concept 1: Function Calling & Tool Schemas (`tools/`)
LLMs cannot run code on their own. Instead:
1. We give Gemini a list of available tool definitions (schemas) specifying:
   - Tool Name (e.g., `web_search`)
   - Description (what it does and when to call it)
   - Parameters (required inputs and data types)
2. When Gemini needs external information, it emits a structured function call:
   `{"name": "web_search", "args": {"query": "Quantum computing latest milestone 2026"}}`
3. Our Python agent catches the request, executes the corresponding Python function, and returns the result to Gemini.

### Concept 2: Lifecycle Hooks (`agent/hooks.py`)
A **Hook** is a piece of code that listens to events in the agent lifecycle without cluttering the business logic.
- **Hook Lifecycle Stages:**
  - `before_tool_call(tool_name, tool_input)`: Captures the exact start time ($t_0$), arguments, and logs the intent.
  - `after_tool_call(tool_name, tool_output, duration_ms)`: Captures the end time ($t_1$), elapsed execution time, output length, and success status.
  - `on_tool_error(tool_name, error, duration_ms)`: Captures exceptions and error states.
- Every event is recorded with an ISO 8601 timestamp (e.g., `2026-09-09T11:25:00Z`).

### Concept 3: Session Memory System (`agent/memory.py`)
Memory consists of two layers:
1. **Conversation History Buffer:** Retains recent dialog turns so the agent knows what was said in the current session.
2. **Fact Recall Store:** Stores critical facts, user preferences, and intermediate research findings explicitly tagged for recall across multi-step conversations.

### Concept 4: Multi-Hop Reasoning (`main.py`)
A **multi-hop question** requires chaining information across multiple independent sources:
```
User asks: "Based on the project PDF, who is the lead researcher, what recent 2026 paper did they publish, and how does it relate to the preference I told you earlier?"
  │
  ├── [Hop 1: File Plugin] ──> Reads local 'project_spec.pdf' (extracts researcher's name: Dr. Jane Doe)
  │
  ├── [Hop 2: Web Search]  ──> Searches Web: "Dr. Jane Doe recent publications 2026"
  │
  ├── [Hop 3: Memory]      ──> Recalls User Fact: "User is interested in Photonic Quantum computing"
  │
  └── [Synthesis]          ──> Synthesizes the final complete answer.
        ▲
        └─ Throughout all hops, [Hooks] record every tool call with exact timestamps.
```

## 🚀 Step-by-Step Implementation Roadmap

### Phase 1: Environment & Dependency Setup
- Create Python virtual environment (`.venv`).
- Create `requirements.txt`:
  - `google-genai` (Official Google Gemini SDK)
  - `duckduckgo-search` (Zero-config web search)
  - `pypdf` (PDF text extraction)
  - `python-dotenv` (Secure environment loading)
  - `rich` (Terminal formatting and clean execution visualization)
- Create `.gitignore` and `.env.example`.

### Phase 2: Tool System & Plugins
- Build `tools/base.py`: Abstract class defining the `Tool` interface.
- Build `tools/search.py`: DuckDuckGo search tool with safety checks and query truncation.
- Build `tools/file_reader.py`: File plugin supporting `.txt`, `.md`, and `.pdf` files.

### Phase 3: Lifecycle Hooks System
- Build `agent/hooks.py`:
  - `BaseHook` interface and `ToolExecutionLoggerHook`.
  - Console visualizer (using Rich) and persistent file logging (`logs/tool_executions.log`).

### Phase 4: Session Memory Module
- Build `agent/memory.py`:
  - `SessionMemory` class supporting message history, fact extraction, and recall.
  - Integration with the agent context prompt.

### Phase 5: Core Agent Engine
- Build `agent/core.py`:
  - `ResearchAgent` class connecting Gemini model, tool dispatching loop, memory, and lifecycle hooks.
  - Multi-turn execution loop handling iterative tool calls until final response.

### Phase 6: Multi-Hop Demo & Verification
- Create sample documents (`sample_data/project_spec.pdf` and `sample_data/research_brief.txt`).
- Build `main.py` featuring:
  1. Interactive CLI mode for custom chatting.
  2. Automated Multi-Hop Demo mode that runs the test scenario end-to-end and validates all 5 requirements.
